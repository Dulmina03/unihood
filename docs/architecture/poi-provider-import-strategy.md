# Public POI providers, licensing and import strategy — UNI-027

Reviewed 17 November 2026 (Asia/Colombo). Specification §7.6, §8.5 and exact §10 UNI-027; dependencies UNI-013 and UNI-020–026, plus [all five ADRs](../decisions/README.md). This issue documents an import design and current provider evidence. It implements no downloader, ingestion job, production write permission, real-data seed or new provider. Public deployment/legal consent remains a later human gate.

## Current provider register

**OpenFreeMap: existing optional browser basemap, not a canonical POI source.** `MAP_PROVIDER=openfreemap`, `MAP_STYLE=liberty|bright`; disabled/missing configuration preserves lists. Only credential-free HTTPS resources on `tiles.openfreemap.org` are allowed by the current adapter. No arbitrary style URL or token crosses the client boundary. [Current implementation and attribution](../ui/maps.md).

The [service page](https://openfreemap.org/) advertises free commercial use without API keys or a map-view/request count ceiling; it offers no SLA. The [terms](https://openfreemap.org/tos/) dated 14 October 2026 prohibit disruptive/unauthorized automated collection. They allow limited offline downloads up to 3,000 tiles or 50 MB, at most four parallel requests and an identifying User-Agent; larger use needs provider contact. UniHood implements no offline pack, bulk map download or tile-derived POI scraping. An authorized adult integrator requirement is separate from student account policy; this review does not choose registration rules.

A read-only HEAD of the configured Liberty style on the review date returned HTTP 200, CORS `*`, `Cache-Control: public` and `max-age=86400`. That observation applies to that response, not every tile/font or an offline-retention promise. Browser HTTP caching follows response headers; no application/service-worker tile cache is added. Map failure has bounded loading and explicit retry; lists remain usable. The draft preview asks permission before sending its viewed synthetic area. Existing exploration requests reveal viewed public areas to the provider; no private boarding geometry or device GPS is supplied.

The [published license inventory](https://raw.githubusercontent.com/hyperknot/openfreemap/main/LICENSE.md) distinguishes MIT project code, BSD-3-Clause style code, CC BY 4.0 style design, OSM data licensing, OFL fonts, CC0 icons and public-domain Natural Earth. Do not treat a software license as a database/content license. Preserve visible OpenFreeMap, OpenMapTiles and OpenStreetMap credits in both maps and exports where applicable; a new style needs its own license/resource review.

The [privacy policy](https://openfreemap.org/privacy/) describes provider/CDN processing and possible error/security IP logs; no-cookie service claims are not anonymity guarantees. Its Site/minors language and the terms' embedded-viewer age distinction require review before public deployment; no new age or identity rule is inferred here. No paid service or new agreement is entered into by this documentation.

**Geofabrik: candidate public OSM extract distribution, not an enabled importer.** The [download service](https://download.geofabrik.de/) offers normally daily OSM extracts under ODbL 1.0. The [Sri Lanka directory](https://download.geofabrik.de/asia/sri-lanka.html) lists PBF files and update resources; no file was downloaded or dataset imported by this issue. Public downloads omit contributor user/uid/changeset fields. [Technical documentation](https://download.geofabrik.de/technical.html) explains buffered clipping polygons and sequence-based changes; a region filename is not proof every feature lies inside the intended pilot. Old diffs have finite retention. No fixed download quota/SLA was established in this review: recheck service rules before scheduling, avoid aggressive polling and do not infer unlimited use.

**Public OSM Nominatim: not configured or approved for UniHood search/import.** Its [policy](https://operations.osmfoundation.org/policies/nominatim/) forbids client autocomplete and systematic area/POI harvesting; its one-request/second ceiling is not permission to batch-extract. UniHood's specification is stricter: use no public Nominatim bulk queries, search shortcut or autocomplete integration. Do not send personal/confidential data. Licensed extracts or a separately reviewed provider/self-hosted service are alternatives, not automatic approvals.

**OSMF raster tiles: not used.** Their [tile policy](https://operations.osmfoundation.org/policies/tiles/) requires attribution, caching and identifying browser referrers and prohibits bulk/offline prefetch. UniHood's no-referrer OpenFreeMap requests must not be repointed at OSMF tiles. Free OSM data does not grant unrestricted public-server capacity. Public Overpass/geocoding endpoints are not an undocumented alternative bulk pipeline. Google Maps scraping is prohibited by specification §7.6. No routing/geocoding/commercial provider is selected by UNI-027; routing remains Phase 5.

A future keyed provider must document permitted browser keys, origin restrictions, quotas/billing, attribution, caching, privacy and failure fallback before activation. Server secrets belong only in server-managed configuration; never public environment variables, checked-in manifests or client URLs. A public browser key is not a private credential and still needs restrictions. Unknown or unavailable terms block activation rather than enabling a fallback provider.

## Data license and attribution boundary

[OSM copyright](https://www.openstreetmap.org/copyright) requires contributor attribution and an ODbL notice. The [ODbL legal text](https://opendatacommons.org/licenses/odbl/1-0/) distinguishes databases, derivative/collective databases and produced works, with obligations depending on use. Review distribution/share-alike and database access obligations for the planned combined dataset before public reuse. Layer separation improves provenance; it does not prove an exemption. A license tag alone is insufficient. Do not redistribute private boarding information to satisfy a database obligation; incompatible rights must block that dataset design.

The [OSMF attribution guidelines](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines) cover databases, maps, search and other outputs. Planned OSM-derived POI cards, list-only browsing, detail/share/SEO and downloadable datasets need source notices too: map attribution alone cannot cover a list with the map disabled. Proposed minimum source wording is “© OpenStreetMap contributors”, linked to the copyright page, with an explicit ODbL link for data exports and manifest notices. These are planned acceptance requirements, not implemented OSM-result UI; current public POI content remains synthetic. The guideline does not replace the legal code. Images, brands, business text, private contacts and personal information can have separate rights. Public accessibility never proves owner consent or authenticity.

## Planned controlled import lifecycle

The following is an engineering design, **not executed tooling**. Existing real-name/import publication support is absent. The current synthetic-only proposal adapter must never be used to bypass that boundary.

1. **Authorize a bounded pilot and source.** A human approves the locality, public service categories, dataset license/attribution and privacy handling before real data acquisition. Record source-policy URLs/review dates and a responsible reviewer. No owner/boarding collection, paid account or final identity decision is implied. Recheck changed terms and data rights before each new source.
2. **Acquire once, reproducibly.** Prefer a licensed dated regional PBF from the approved distributor, then filter locally. Record exact source URL, retrieval UTC time, provider snapshot/replication metadata, locally computed SHA-256, observed size, tool/version and category-mapping revision in an import manifest. Null/unknown evidence is a stop, not a fabricated checksum. Validate HTTPS origin, bounded download/parser size/time and available storage before future execution. Use an identifying agent, conditional retrieval, one bounded transfer and backoff/Retry-After for failures; these are conservative UniHood defaults, not an asserted provider quota. Do not commit extracts or raw tags. Do not geocode rows through public Nominatim.
3. **Quarantine and minimize before mapping.** Parse in isolated staging, never directly into public projections. Allowlist useful public business tags/categories; discard contributor identities, contacts/addresses, arbitrary description/URL/media and residential/boarding/owner/vacancy/fee data. Ambiguous mixed residential/public sites are held or excluded, not inferred as public. Exclude invalid/out-of-pilot geography after local clipping; buffered distributor bounds are insufficient. Staging access/retention requires review. No raw record or rejected coordinate may appear in public logs, errors, counters with precise geography, caches or search indexes.
4. **Use source identity, not proximity as identity.** Stable provider namespace `openstreetmap`; exact external identity includes object type (`node`, `way`, `relation`) and ID. Version/replication sequence are evidence, not replacement identities; distributor mirrors must not create separate source namespaces for the same OSM objects. Never normalize opaque external IDs or equate two businesses by shared building/coordinates/name. Feed eligible candidates into the existing normalization/spatial/text/source/pending recheck. Conflicts, changed geometry and incomplete scoring hold for review; no automatic destructive merge, source reassignment or owner-privilege transfer.
5. **Validate a usable public entrance.** A POI coordinate, polygon centroid, label point or nearby road is not evidence of an accessible business entrance. Preserve source geometry privately only where approved; publish an entrance only after appropriate evidence/review confirms public access. Never copy a campus gate from a POI guess, invent coordinates, snap a boarding to a public business or imply routes/distances. Name/category/coordinate validity does not establish real-world correctness or owner authority.
6. **Recheck and stage a reviewed change set.** Store source/version/license provenance separately from review and last-confirmed times. Current `data_kind=VERIFIED` requires real verification; do not assign it from download time, license existence or an OSM edit timestamp. Current proposals are SYNTHETIC-only; a future approved real-data path needs reviewed contracts/storage and paired additive migrations before use. Reuse one-client transactions, cross-table exact-source constraints and lock ordering; the existing synthetic matcher/service is a reference, not a ready production importer. Review every prospective create/update/hold with count-only redacted reports; no auto-publication, public HTTP import endpoint or protected-write bypass.
7. **Promote only eligible data after gates.** A future authenticated, audited importer may apply approved public-service changes only after privacy/rights/entrance/duplicate review. Production exposure still requires Phase 7 protections; the real-data pilot remains UNI-081. Create source refs/aliases and eligible public projection atomically. Do not overwrite manually corrected/owner-controlled data with provider values. Preserve original licensed layers and required attribution; enforce existing public-only serializers on every list/detail/map/cache/share/SEO path. No import creates boarding map consent, students' boarding pins, official prices, vacancies or ownership.
8. **Refresh safely and support rollback.** Verify sequence continuity, source snapshot and mapping version; gaps/expired diffs require a reviewed baseline, never blind replay. Idempotency keys bind actor/batch/source version and validated content. Same source/version/body is a no-op/replay; incompatible same-key bodies fail. A disappeared/retagged feature requires review, not bulk deletion of canonical/shared records. Use an audited forward compensation that removes/revokes only the batch-owned public projections/source changes while retaining evidence and unrelated work; backup/restore validation precedes real promotion. Preserve migration checksums and extension ownership; no CASCADE, persistent-volume removal or reset.

## Planned import manifest

[Non-executable manifest template](../data/poi-import-manifest.example.json) distinguishes unknown values from observed evidence. No URL/hash/time/coordinate in it describes an imported artifact. Future validation must reject DESIGN_ONLY/incomplete manifests before any write. Batch IDs/checksums and tool versions must be real observations. Keep credentials, raw tags, personal data and private points out of manifests committed to the repository. A license document snapshot may be retained only under its own rights; linking/review metadata alone is not proof of consent.

The manifest supplements existing `place_source_refs` (`provider`, exact `external_id`, `source_version`, `license_tag`), canonical provenance and public location source/last-confirmed fields. It is not a new database schema or proof those columns fully support an importer. `verified_at`, `last_confirmed_at`, source edit time, acquisition time and moderation decision time are distinct facts. Missing evidence remains null/unavailable; no synthetic row is relabeled verified.

## Acceptance before any future importer runs

Use repository-authored synthetic extracts first, owned tmpfs databases and mocked network responses. Require deterministic replay, malformed/bounded input rejection, rate/backoff/timeout behavior, license/source unknown failure, snapshot/sequence drift, source-ID geometry changes, shared-building distinct businesses, concurrent source/pending races, transactional rollback, attribution in map/list/detail/export, stale removal/cache invalidation and backup/compensation tests. Test private/residential/contact rejection across outputs without public geometry/fingerprints. No upstream service belongs in ordinary CI and no real boarding example belongs in fixtures. Existing UNI-020–026 automated checks are regression evidence, **not proof these future importer scenarios have run**.

Outstanding human/release items: pilot boundaries/categories and field verification, rights compatibility/share-alike delivery, public-provider age/privacy wording, real-source retention/erasure and operational budget/permissions, reviewed real-data schema/path, authentication, attribution across new output modes and real importer/restore tests. These do not require code or provider activation in this documentation issue. Public launch remains gated; no real import is authorized or implemented here.
