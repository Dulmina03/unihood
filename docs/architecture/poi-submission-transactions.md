# Pending public POI transaction foundation — UNI-025

Specification §5.5, §6.1 steps 2/5–7 and exact §10 UNI-025. M2/M5; depends on UNI-020–024, existing identity/permission interfaces and all [five ADRs](../decisions/README.md). Internal foundation only: **no new submission REST route, proposal wizard, publication/moderation workflow or production authentication**. UNI-026 owns the guarded contribution path; Phase 7 owns final identity policy. [Actual verification](../verification/UNI-025/README.md).

## Held intents and authority

Migration 005 adds private `poi_pending_proposals`, `poi_pending_source_refs` and `poi_submission_requests`. Claimed public-business entrances and distinct explanations stay outside the public geometry projection. All records are explicitly synthetic, held PENDING, category-scoped public POIs; synthetic names/actor references and bounded valid geography are constrained. No boarding/property/owner fields, public map point, live availability, fee or privilege transfer is created. No new grants are issued. The PostgreSQL schema name `public` does not make these tables a public API: current read queries/DTOs never select them.

`PoiSubmissionService.prepare(actor,input)` accepts only an actor actually issued by the existing local/test adapter, a repository environment eligible for synthetic data, and current `canSuggestPlace` permission. Production/staging and forged actor objects fail before DB access. This internal service deliberately denies even hypothetical VERIFIED_ACCOUNT contexts until final auth integration is reviewed. Arbitrary HTTP identity headers cannot select actors. The adapter now verifies the original identity/auth status as well as private issuance, so mutating an issued context cannot switch the idempotency namespace. The service captures that identity before waiting and rejects mutation during permission resolution.

Shared internal contracts accept a UUID idempotency key, strict synthetic public POI draft, explicit update-existing or distinct-with-reason choice, and optional exact source reference with license metadata. Source IDs are opaque, preserving whitespace/Unicode forms; name normalization never rewrites them. Source fields are **internal trusted-adapter inputs**, not a new arbitrary browser lookup API. License metadata is not provider consent or import permission; no external data is requested here. These contracts are not registered as live public OpenAPI operations. Cancel is a UI action, not a persisted submission.

## One transaction, fresh recheck

The existing bounded pool supplies one checked-out client for explicit READ COMMITTED BEGIN → work → COMMIT; errors roll back before release. Rollback failure discards the connection. Existing statement/query/connect limits remain; new transaction-local lock and idle deadlines bound waiting. Unexpected driver/error details become ServiceUnavailableException, never raw SQL/credentials. A deliberate application conflict remains a sanitized 409 for the eventual controller.

Each preparation acquires transaction-level advisory key `(25025,1)` **before** reading idempotency state or matching. This conservative single public-POI submission scope avoids geographic-cell boundaries and moved-source races. It serializes cooperating service callers across pools/processes; it is not a production throughput optimization. Locks end with the transaction and cannot remain on an idle pooled session. READ COMMITTED allows the post-lock queries to see earlier committed work. These choices follow [PostgreSQL advisory lock semantics](https://www.postgresql.org/docs/17/explicit-locking.html#ADVISORY-LOCKS) and [READ COMMITTED snapshots](https://www.postgresql.org/docs/17/transaction-iso.html#XACT-READ-COMMITTED), and are independently exercised against the pinned PostgreSQL/PostGIS image.

Idempotency primary key is `(actor_ref,idempotency_key)`. A versioned SHA-256 of the validated canonical field order detects changed payloads; only the hash and minimal result are stored, not a hidden request snapshot. Same key/body returns the original own-intent result; different body conflicts without exposing old content. Other actors cannot replay another actor's result. Permission/environment checks happen on every call, before cache access. **Privacy exception:** a cached existing-public-place pointer is revalidated; revocation/archive/merge or removal from the public projection returns generic REVIEW_REQUIRED instead of repeating a now-ineligible public label. That intentionally takes precedence over byte-identical replay; it does not alter canonical data or expose a new ID.

Inside the same transaction, exact canonical/pending source IDs and nearby pending POIs are checked again regardless of an earlier empty browser preflight. Pending matching uses public-business category, 50m geography and normalized-name equality/illustrative similarity >=0.6. Pending matches return a generic review result, never another actor's pending ID/name/geometry/reason. Canonical matching reuses UNI-023 through the **same client**, with truncation/incomplete results held for review. Update-existing must reference a current eligible candidate; an exact public source identity redirects to the existing public ID even after geometry drift. Private/unpublished canonical source collisions return generic review only.

A distinct explanation can create a held intent, including an ambiguous claimed separate business; it never clears publication or forces a second canonical identity. Same-place concurrent intent attempts produce one pending intent and review for the other caller. Different businesses can share a point/building and remain separate. Thresholds are synthetic heuristics, not proof of identity; low-recall multilingual/pending aliases and uncertain same-category identities still need contextual review. No destructive merge, automatic ownership transfer or full §6.3 whole-product coverage is claimed. Pending media/contact/boarding evidence remains deferred.

## Source references and writer contract

Pending `(provider,external_id)` is unique, as canonical source IDs already are. Bidirectional triggers acquire the same transaction-level lock and reject cross-table collisions on INSERT/key UPDATE, including direct canonical source writers. Existing source rows are neither backfilled nor rewritten. Null canonical external IDs retain their existing meaning (no asserted provider identity). Opaque keys are compared exactly; a conflict is not authority to transfer a source to another record.

Cross-table triggers require READ COMMITTED and fail closed under repeatable-read/serializable transactions rather than checking against a stale snapshot after a lock wait. This is an explicit compatibility restriction for future import tools, not a claim that stronger isolation is generally unsafe. Real concurrent tests prove both insertion orders and the isolation refusal. No new trigger auto-publishes or changes places, source rows, official fields or ownership.

All future application publication/import writers must use coordinated final rechecks, preserve pending evidence and review source adoption in one transaction. Advisory locks alone cannot deduplicate arbitrary administrator SQL, fuzzy identity or writers bypassing the protocol. Direct canonical source uniqueness across pending/canonical tables is additionally database-enforced. There is no source-promotion, cancellation/release, merge or lifecycle deletion API in UNI-025; those must not bypass the reservation in later work.

## Migration, operations and deferred work

Apply migration 005 through normal ordered `pnpm db:migrate`, preserving `.env`, data and extension ownership. No old SQL is edited. Table/index/function creation refuses conflicting existing objects instead of silently adopting them. Down locks canonical sources and new tables, refuses **any populated pending/request/source table**, and uses RESTRICT for dependencies. Empty down/up/repeat is supported; no CASCADE, volume deletion or persistent seed/reset is required. Plan reviewed production DDL scheduling; no public deployment is performed here.

Idempotency records/held evidence have no automatic expiry or destructive cleanup. Only synthetic fixtures are supported now; real identity evidence, retention/erasure policy, production abuse limits, distributed throughput, risk-state transitions, contribution history, source promotion and actual public submission remain later reviewed work. No routine admin dashboard is introduced. The service does not silently declare unscreened free text/media safe; UNI-026 must validate content, preserve editable drafts on review outcomes, and integrate moderation before any eventual publication.
