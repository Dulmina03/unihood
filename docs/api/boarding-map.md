# Consented synthetic boarding map — UNI-034

See [visibility rules](boarding-visibility.md), [privacy architecture](../architecture/boarding-privacy.md), [OpenAPI](openapi.json) and [actual verification](../verification/UNI-034/README.md).

Public `GET /api/v1/boardings/map` accepts only page/pageSize/q; returns a bounded title-ordered `BoardingMapPage`. Geometry comes exclusively from a separately selected, current owner-consented entrance. AREA_ONLY, HIDDEN, community, archived, merged, disputed, unpublished, mismatched revision/consent and deployed synthetic records are excluded. Private verification locations are never queried. No spatial filter/order, price, vacancy, route, media or contact inference. Price is null and vacancy unknown. Source labels explicitly describe fictional data and synthetic authority, never real verification.

Direct loopback-only `GET/POST /api/v1/owner/boardings/:boardingId/map-settings` requires issued property management; public-map POST additionally requires exact-location capability. Strict POST is `{expectedRevision, choice}` where choice is the existing mode-specific explicit consent contract. No client actor, arbitrary coordinates or unreviewed public text is accepted. This seam changes only a known preinstalled fictional fixture; production/staging writes fail closed. CORS is restricted to the configured loopback web origin. No public proxy promotes identity.

To prepare an **optional synthetic demo** on an existing local database after reviewing the migration and preserving its data, use the existing local setup, then `pnpm db:migrate` and `APP_ENV=local pnpm db:seed:boardings --owner-demo`. This inserts one closed HIDDEN fixture for existing adapter property A; repeat seeds verify exact fields and refuse conflicts without overwriting local changes. After changing visibility the original seed can deliberately report a conflict; do not reset or overwrite the property to silence it. The ordinary directory and private-ad seeds stay separate. No seed automatically publishes a public point.

Run the existing explicit local/test **owner-a** adapter on loopback (see [actor setup](contracts-and-actors.md)); arbitrary identity headers grant nothing. Open `/owner/map`, load settings, choose the fictional entrance at latitude 0/longitude 0, acknowledge map consent and external-copy limits, then publish the fixture. Choose a synthetic university/campus in `/explore`, switch to Boardings, and inspect the marker/list/preview. The point is fictional world-origin geometry, not near a real university or a live accommodation offer. Hide/revoke or choose area-only in owner tools, then watch current explorer data refresh. Routes/distances are unavailable.

The transaction locks the property, rechecks the revision, deletes active public geometry, updates the same canonical property, creates a new curated listing revision and records a minimal private event. A concurrent/replayed stale revision yields conflict. No geometry is copied into historical revisions/events. There is no map/search materialized cache or geometry persistence in the browser. Read responses/proxies are no-store and metadata is generic. Open clients revalidate best effort every five seconds and on lifecycle events; unknown/offline failures clear visible old points and retain the list/error path. External screenshots, prior responses or suspended third-party clients cannot be recalled; no absolute revocation SLA is claimed.
