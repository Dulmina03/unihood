# Held structured reviews and own contribution status — UNI-043

Specification §3.6, §7.3–7.4, §10 UNI-043; ADRs 0001–0005 remain intact. Only an issued loopback local/test contributor capability can use these endpoints. Guests, staging/production/unknown modes, arbitrary identity headers, cross-site and forwarded requests cannot select an actor or gain authority. No final registration, publication, verified-stay verification, official fact change or support dashboard is implemented.

`POST /api/v1/contributions/review` accepts strict `{key,targetType,targetId,reviewKind,rating?,observation?,sourceConfidence,sourceLabel,syntheticAcknowledged:true}`. `targetType` is `BOARDING` or `POI`; `targetId` must be a canonical public `places` row that is currently `ACTIVE`, unmerged and `SYNTHETIC` with the matching `kind`. A withdrawn/merged/publicity-unknown target has the same unavailable result without revealing why.

`reviewKind` is `GENERAL_OBSERVATION` or `VERIFIED_STAY`. "Stay-based observation" is a community-submitted label only and never verifies that anyone stayed; the API and UI never claim a verified stay. `rating` is an optional integer 1–5; `observation` is optional 1–1000 characters with control/bidi restrictions. At least one rating or a non-empty observation is required. `sourceConfidence` is `COMMUNITY_SUBMITTED` or `SOURCE_CHECKED`; `sourceLabel` is `SYNTHETIC` or `HELD_UNVERIFIED`. No private address, contact, owner claim, rent, price or vacancy field is offered.

Conflict prevention: when the target is a boarding advertisement and the requesting actor can manage that property, submission is refused with the same protected result. The check uses the existing permission service; it does not disclose ownership or another actor's authority. Conservative sensitive-text signals (contact-like number sequences, address/apartment/coordinate/phone/contact/owner/rent/price/vacancy wording, URLs, e-mail markers) route the held review to `NEEDS_EVIDENCE`; their absence is never certified safe and never publishes anything.

Migration 016 stores an actor-scoped immutable held record with a canonical FK (`target_id → public.places`), target type, review kind, nullable rating, bounded observation, source confidence/label, review state and submission time. Actor/key/payload replay is idempotent; a changed payload returns 409 without overwriting history. A different actor has a separate receipt. Failure rolls back atomically. Populated rollback refuses and `RESTRICT` protects dependencies; earlier migrations remain immutable.

Success 200/no-store contains only own contribution ID, `HELD_REVIEW`, `PENDING`/`NEEDS_EVIDENCE`, `SYNTHETIC` and `published:false`. Never expose stored observation text, source notes, contacts, actor IDs or geometry.

`GET /api/v1/contributions` is protected even though it is a GET. Its existing actor-scoped history additionally returns `REVIEW` items with ID, current held state, submission timestamp, `SYNTHETIC`, optional currently eligible public target link, review kind and optional rating. No stored observation text, source confidence/label notes, contacts, payload hashes or other-actor identity are projected. Published/rejected decisions remain later governance work, not simulated successes.

UI-27 `/contribute/review?type=POI|BOARDING&id=<canonical-public-UUID>` starts from the contribution hub and accepts exactly those two query fields; malformed, extra or non-UUID fields do not select a target. Both map-visible and private-location (`AREA_ONLY`/`HIDDEN`) boarding advertisements are accepted as text targets without reading residential geometry. The form separates general from stay-based (non-verified) context, takes an optional rating, bounded observation, source confidence/label and explicit synthetic acknowledgement, previews the actual submission, retries the unchanged request with the same key, and shows a held receipt. Drafts remain in memory and are excluded from local/session storage and share URLs. Both pages use generic noindex metadata and no-store/omit-credential API calls. Clearing local inputs cannot retract a server-received request.

Local demonstration: use the existing synthetic database and migration/seed instructions. Explicitly run the loopback local API with `APP_ENV=local`, development Node mode, `ENABLE_SYNTHETIC_ACTORS=true`, `SYNTHETIC_ACTOR=contributor`, matching `WEB_PORT` and `API_HOST=127.0.0.1`. Start `pnpm dev` and open `/contribute/review?type=POI&id=<seeded public POI UUID>`. Use fictional context only. Normal guest services stay read-only; no public server should enable this simulator.
