# Editorial advertisements — UI-06 / UI-07 / UI-08

UNI-031 adds `/advertisements` and canonical `/boardings/[id]`. Existing landing “Browse Advertisements” and explorer boarding-category links open the feed; map pins remain deferred. Guest navigation requires no registration or location permission. Public APIs, safe optional seeds and limitations are described in [the API guide](../api/boarding-advertisements.md).

The approved `03_advertisements_editorial.png` and `04_boarding_details_editorial.png` informed the navy header, Campus Teal/serif hierarchy, photographic banner, source segments, generous responsive cards, editorial privacy column and asymmetric detail/gallery + action rail. Only the existing licensed illustrative campus asset is reused, with caption and `/photo-credits` provenance; no new property photograph or endorsement is invented. Cards and gallery show “Photos not supplied.” This deliberately differs from the reference photo inventory. No fake rent, vacancies, distances, nearby scores, facilities, ratings or contact actions are copied. Actual consented media/rooms/contact/fees/map/reviews belong to later roadmap issues.

Native GET filters and validated native source/pagination links preserve search, privacy/source and order on reload and browser Back/Forward. Native filter navigation avoids replacing an editable stale form during an in-flight RSC transition. Changing filters resets page; clearing returns to the full preview set. Only curated public title/locality is searchable. Unknown/repeated/spatial URL fields show a sanitized reset state. API-backed SSR, a feed route loading skeleton and explicit retry skeletons, empty/missing results, network error and bounded retry preserve useful navigation. Retry aborts on unmount/replacement and restores heading focus after React commits. Share uses a native accessible modal with Escape/focus restoration, a read-only selectable canonical ID link and clipboard fallback; filters and identity are excluded.

Responsive feed: three cards plus editorial rail at desktop, two cards with the rail below on tablet, one card/mobile and compact filters. Detail uses a spacious asymmetric empty gallery and sticky desktop information rail, stacked on mobile; no sticky fake contact control obscures content. Source, privacy and uncertainty use text as well as color. Existing design-system header, badge/privacy/source, field, notice, skeleton, modal, icon and button components are reused. No boarding Save button is presented before a usable boarding-favourites experience exists; entrance favourites remain unchanged.

Automated screenshot/axe/keyboard/320/768px and real database E2E results and limitations are recorded in [UNI-031 verification](../verification/UNI-031/README.md). Screenshots do not imply human visual approval, screen-reader certification, live inventory or real-provider verification. The human approved these current synthetic-only UI-06/UI-07/UI-08 mobile/desktop feed and private-detail layouts on 17 November 2026; later media/contact/pricing/publication and manual AT are outside that approval; detailed Phase 1 manual accessibility remains deferred to Phase 6.
