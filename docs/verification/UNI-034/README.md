## Scope and boundaries

`GET /api/v1/boardings/map` returns only current owner-consented PUBLIC_MAP synthetic entrances. It rechecks active canonical identity, synthetic provenance, current published owner revision, property authority/mode/consent, curated preview and separately selected point/purpose/consent timestamp. No private table, raw property description, verification coordinate, contact, media, inventory, proximity ordering, route or unsupported distance is used. Existing advertisement feed/detail remain private-mode only; the public map summary lives in Explore.

New paired migration 009 widens curated mode constraints without editing 007/008, adds separate public entrance and private minimal visibility-event tables, and refuses rollback with populated new state or dependencies. No extension ownership change, CASCADE, persistent-data deletion or automatic dev migration. Public geometry is deleted atomically on hide/area switch; previous listing revisions and canonical identity survive. Audit events contain mode/revision/issued synthetic actor reference, never coordinates or private evidence. No claim of encryption, production role isolation or operational retention policy beyond existing boundaries.

Protected owner map settings operate only on the separately seeded closed fictional adapter property A. Existing property-specific issued synthetic actor checks apply; public mode additionally requires exact-location permission, deliberately selected fictional entrance and both explicit acknowledgements. Revision mismatch returns 409; a lost response requires reloading, never a claim of successful save. No new owner grant, claim, canonical creation, real-data publication or production auth shortcut. Official fees/vacancy/media/contact/routing and later boarding detail/compare work remain deferred.

Explorer preserves existing gate/POI paths, mobile sheet, Map/List and validated canonical URL state. Public boarding query is title-only with bounded pagination, never private spatial filtering. Current response parsing is strict; late responses are ignored. No persistent point/consent snapshot, HTTP/SW cache, coordinate URL or geometry in SEO/share metadata. Live boarding data revalidates at best-effort five-second intervals and on focus, online/offline, visibility and pageshow events; refresh/failure clears visible old markers and preview. This is not a guaranteed offline/background revocation deadline and cannot recall external copies or prior network responses. Map resource/provider rules remain unchanged; browser provider resources and synthetic fixtures are explicitly mocked/labeled.
