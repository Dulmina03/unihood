## What the tests establish

Contract tests cover all eight enum families, numeric/query bounds and coercion/unknown-field rejection, five publisher/visibility variants, recursive private extras, consent/verification prerequisites, owner-only prices, hidden locality, malformed prices, confirmation intervals, expired/future vacancy downgrade, public-only validation details and strict paginated items/page-size consistency. Response projection schemas are not owner-write request authorization.

Actor tests cover explicit compatible environment opt-in, staging/production/unknown/missing environments, NODE_ENV production override, disabled/wildcard/nonliteral bindings, unknown fixtures, actual nonloopback/proxied/cross-origin/rebinding requests, caller-created/cloned actors and mutated memberships, cross-instance capabilities, property A/B separation and limited operation grants. Forged VERIFIED_ACCOUNT contexts or X-User-Id/X-Role headers do not create authority. Local synthetic actors are not real verified accounts.

HTTP tests use controllers declared **only in the test module**, excluded from production source/build/OpenAPI. They exercise real guard decisions: owner A allowed on A but not B; contributor cannot impersonate an owner; unannotated mutations denied even to the synthetic owner; staged/production-like configurations cannot grant writes. Validation rejects repeated query arrays and unknown/sensitive keys. 400/401/403/404/409/422/429/500/503 failures use generic messages, safe details, server-generated UUIDs and no-store. Unexpected exceptions, malformed JSON and unknown URLs do not echo secret canaries, SQL/stack text or client correlation IDs. Existing flat readiness 200/503 semantics remain an explicit monitor protocol exception, with exact status-specific schemas.

## Scope and limits

No final signup/provider/owner proof, account/session/recovery, domain workflow, database schema/migration, private evidence/contact/media pipeline or frontend integration was implemented. No real listing/identity data was introduced. Public boarding schemas have no corresponding live endpoint yet. Free-text address/contact detection, media consent/EXIF processing, real property proof, consent persistence/revocation, production memberships and full privacy/inference enforcement remain future owning-module work. Schema parsing alone is not a universal private-data scrubber or authorization proof.

Current-time freshness and cross-field interval/page-size checks are runtime refinements beyond generated JSON Schema; they are documented, tested and not falsely represented as complete OpenAPI semantics. Readiness's legacy flat 503 outcome is preserved intentionally rather than silently breaking the existing Docker monitoring protocol. Local actors must never be exposed through public proxies/tunnels; these development safeguards do not substitute for final authentication.
